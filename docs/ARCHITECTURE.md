# 鉴源 GenSight · 架构设计文档

> 版本：v1（2026-09-29）
> 状态：已评审，待按 Phase 1 落地
> 范围：汽车及相关产业垂直尽调平台（首个垂直包），后续扩展到其他行业

---

## 1. 战略定位

### 1.1 一句话

**用公开免费数据 + 卫星遥感 + 真实财务法证，做可追溯的汽车产业链真相。**

### 1.2 差异化判断

| 竞品 | 做的 | 我们不做/做不了的 |
|---|---|---|
| 企查查 / 天眼查 | 企业工商信息 | 不重复做工商（免费源反爬风险高） |
| Wind / Bloomberg | 金融数据 | 不做付费行情 |
| 券商研报 | 主观观点 | 不做主观判断 |

**我们做、且别人没做的**：把汽车产业链的「采购 / 股权 / 产能 / 风险」用**免费公开数据 + 真实计算**还原成一张**每条结论可点开来源证据**的尽调图谱。

### 1.3 "特别"的三个真实能力（不是三个唬人术语）

1. **真实财务法证** —— Benford 定律 / Beneish M-Score / Altman Z-Score，从披露文件抽数后**真算**（纯数学，零成本）。
2. **真实卫星实证** —— ESA Copernicus **Sentinel-1 SAR**（免费）监测目标工厂是否真实开工，国内几乎无人做，是产品最强差异化。
3. **真实交叉对账** —— 供应商 ↔ 客户双方年报互为印证，是"鉴源"二字的落点。

### 1.4 核心原则（不可妥协）

> **能真算的做真，不能真算的砍掉，绝不留假数据充门面。**

这是对旧版"九维法证"（Ricci 曲率 / Pearl 因果 / 渗流相变等预写模板文本）的彻底否定与修正。

## 2. 现状盘点（继承什么、抛弃什么）

### 2.1 保留（工程底座扎实，直接复用）

- **后端骨架**：Express + better-sqlite3，`server-*.ts` 模块化拆分清晰。
- **鉴权安全**：scrypt / HttpOnly Cookie / SameSite / `timingSafeEqual` / API Key 脱敏 / 不信任请求体。
- **限流与缓存**：IP 短窗口 + 每日配额；按 provider+schema 版本化缓存，命中不扣配额。
- **披露采集管线**：巨潮(A股) + SEC EDGAR(美股)，pdfjs-dist 抽文本 + LLM 结构化抽取。
- **AI 抽象层**：Gemini / DeepSeek / Qwen 三 provider 统一封装，后端持有 Key。
- **前端 6 层递进 UI**：交互骨架保留，数据来源替换为真实。
- **商业闭环**：免费分析 → 限流 → 注册登录 → 付费报告 → 邮件投递。

### 2.2 抛弃 / 重写

- **假法证模板**（`src/utils/forensicDataHelper.ts` 里预写的中文叙事 + 固定数字）→ 重写为真实计算（见 §6）。
- **平铺数组关系**（`types.ts` 的 upstream/downstream/investments 数组）→ 迁移到知识图谱（见 §4）。
- **硬编码汽车静态库**（`src/data/automotiveIndustry.ts`）→ 过渡期保留，最终由采集+抽取动态生成。

## 3. 目标架构（5 层）

```
┌────────────────────────────────────────────────────────────┐
│ 应用层     6 层递进 UI（保留）+ 报告 + 证据工作台              │
├────────────────────────────────────────────────────────────┤
│ 分析计算层  ★ 真实模型：Benford / Beneish / Altman / 图中心性  │
│            ★ 遥感：Sentinel-1 SAR 工厂活动时序                │
├────────────────────────────────────────────────────────────┤
│ 知识图谱层  汽车本体 + 图存储 + 证据链索引（每条边挂证据）       │
├────────────────────────────────────────────────────────────┤
│ 结构化抽取层 LLM 只做「抽取」不做「生成」；schema 驱动           │
├────────────────────────────────────────────────────────────┤
│ 采集层     Connector 插件化：巨潮 / EDGAR / HKEX / MOPS / …   │
└────────────────────────────────────────────────────────────┘
```

### 3.1 分层职责与依赖方向

依赖方向严格自上而下（上层依赖下层，下层不感知上层）：

- **采集层**：每数据源一个 Connector，输出统一的 `RawDisclosure`（原文 + 来源元数据）。职责：只"拿原文"，不做分析。
- **结构化抽取层**：schema 驱动，把原文抽成结构化字段；每个字段标注 `source_section`（来源页码/章节）。**这是 LLM 唯一的使用点。**
- **知识图谱层**：把结构化数据落到图（节点=实体，边=关系，边挂 `Evidence[]`）。提供图查询与中心性计算。
- **分析计算层**：读图谱数据，跑真实模型，输出可复算的结论（输入、公式、结果都可展示）。
- **应用层**：渲染 6 层递进视图，每条结论都能下钻到证据。

## 4. 领域本体（汽车产业链）

参考 [Eclipse Tractus-X / Catena-X 本体](https://github.com/eclipse-tractusx/sldt-ontology-model)，不自行发明。

### 4.1 实体层级（Tier 链）

```
整车 OEM → Tier-1 总成 → Tier-2 部件 → 材料/芯片/设备 → 矿产
```

### 4.2 关系类型

`供应(supply)` / `采购(customer)` / `股权(equity)` / `合资(JV)` / `竞争(competitor)` / `关联交易(related_party)`

### 4.3 关键实体属性

- **工厂**：名称、经纬度、产能、开工状态（遥感佐证）
- **公司**：代码（A股/港股/美股/台股）、环节定位、市占率
- **关系**：采购产品、金额口径（已披露/估算/未披露）、单一来源风险、证据列表

### 4.4 证据（Evidence）——"可追溯"的地基

每条实体/关系/结论必须挂证据：`{ 来源, URL/页码, 采集时间, 置信度 }`。前端任何数字都可下钻到原始证据。

### 5.2 付费兜底原则

- **默认零付费**：第一版只用「披露文件 + 行业统计 + 遥感」。
- **按需按次付费**：工商股权穿透确有需求时，用企查查/天眼查**按次查询**（非包年），仅在股权穿透链路调用。

## 6. 真实法证计算层（核心改造）

### 6.1 替换表

| 旧（假模板） | 新（真计算） | 成本 |
|---|---|---|
| Benford 定律（写死 p=0.52） | 抽取财报明细科目 → 真算卡方检验 | 零（纯数学） |
| Beneish M-Score（写死 -2.48） | 抽取 8 个财务指标 → 真算 | 零 |
| Altman Z-Score（写死 3.82） | 同上，真算 | 零 |
| SAR 遥感（写死 -7.4dB） | Sentinel-1 SAR 时序 → 真监测开工率 | 免费数据 |
| 三角对账（写死数字） | 供应商/客户双方年报交叉核对 | 零 |
| ~~Ricci 曲率 / Pearl 因果 / 渗流相变~~ | **砍掉** → 真实图论指标（度中心性/介数中心性）识别"单点咽喉" | 零 |

### 6.2 实现要点

- 每个模型 = `{ 输入指标, 计算公式, 计算结果, 阈值判定, 数据来源 }`，结果可复算、可展示，绝无写死数字。
- 财务指标从 `extracted_data`（真实抽取）读取；抽取不到则如实返回"数据不足"，不返回伪结论。
- 图中心性用度数/介数中心性识别单一来源依赖（对应旧版"单点咽喉"的意图，但用真算法）。

## 7. 多行业扩展机制（先汽车、后扩展）

每个行业 = 一个**垂直包**，四件套：

```
vertical/automotive/
  ontology.ts      # 行业本体（实体/关系/属性 schema）
  connectors/      # 该行业数据源采集器
  extract-schemas/ # LLM 抽取 schema
  models/          # 该行业法证模型
```

新增行业 = 新写一个垂直包，复用 5 层骨架。**建议第二个行业选半导体**（披露源通用：巨潮/EDGAR/台股，复用率高）。

---

## 8. 成本模型

- **数据源**：全部免费（披露文件 + 行业统计 + Sentinel-1）。
- **LLM**：只做结构化抽取（刚需，唯一持续成本）；砍掉长篇生成（最烧钱、价值最低）。抽取用便宜的 DeepSeek/Qwen，Gemini 仅兜底。
- **计算**：Benford/Beneish/图中心性全本地，**零边际成本**。
- **缓存 + 增量采集 + 定时任务**：把重复调用压到最低（现有缓存机制已具备）。

| # | 决策 | 理由 |
